# hsrsbapp プロジェクト構成

## 概要

**hsrsbapp** は、個人向けの各種記録・管理機能を提供する Web アプリケーションです。
無料枠のクラウドサービスで運用することを前提に設計しています。

| 項目 | 内容 |
|------|------|
| リポジトリ構成 | モノレポ（フロントエンド・API 定義・バックエンドを同一リポジトリで管理） |
| フロントエンド | Angular 21（SPA） |
| バックエンド（現状） | Supabase Edge Functions（Deno） |
| バックエンド（将来） | Spring REST API（`backend/` ディレクトリへ移行予定） |
| データベース（現状） | Supabase（PostgreSQL） |
| データベース（将来） | Neon（PostgreSQL）※後述 |
| API 契約 | OpenAPI 3.0（`openapi/`） |

### 機能（画面）一覧

機能は `frontend/src/app/features/` 配下に 1 機能 = 1 画面として実装します。

| 機能 | パス | 説明 | 状態 |
|------|------|------|------|
| reading-recorder | `/readingRecorder` | 読書記録 | 実装中 |
| money-recorder | — | 家計簿 | 未実装（予定） |

### デプロイ方針

| レイヤー | 採用（予定） | 備考 |
|----------|-------------|------|
| フロントエンド | GitHub Pages | 静的ホスティング。無料枠で運用可能 |
| バックエンド（将来） | Render（無料 Web サービス） | Spring REST API のホスティング先。Supabase Functions から移行予定 |
| データベース（現状） | Supabase | 開発・移行期間中に使用 |
| データベース（将来） | Neon | 長期無料運用を見据えた移行先（**Render 無料 PostgreSQL は採用しない**） |
| PWA | — | 計画段階。オフライン対応・ホーム画面追加を想定 |

詳細は [ホスティング・インフラ方針](#ホスティングインフラ方針) を参照。

## ホスティング・インフラ方針

無料枠のクラウドサービスで長期運用することを前提に、各レイヤーの選定方針を定める。

### 目標アーキテクチャ（将来）

```
GitHub Pages (Angular SPA)
        ↓
Render (Spring REST API)  ← 無料 Web サービス
        ↓
Neon (PostgreSQL)         ← 無料枠・期限なし
```

### 無料枠サービスの比較（データベース）

| サービス | 長期無料で使えるか | 主な制約 |
|----------|-------------------|----------|
| **Supabase** | 使える（条件付き） | **7日間アクセスなしで一時停止**。データは保持され、90日以内に復元可能。Pro（$25/月）で停止なし |
| **Render PostgreSQL** | **不向き** | **作成から30日で失効**。14日の猶予後にデータ削除。開発・テスト用途のみ |
| **Neon** | 使いやすい | 0.5GB、月100 CU-hours。**期限なし・休止なし**（アイドル時はスケールトゥゼロ） |
| **Railway** | 実質なし | $5 のトライアルクレジットのみ。継続無料ではない |

**結論:** Render の無料 PostgreSQL は長期運用に不向き。**DB は Neon を採用する。** Render は API（Spring）のホスティングに使う。

参考:

- [Supabase: Project Pausing](https://supabase.com/docs/guides/platform/free-project-pausing)
- [Render: Deploy for Free](https://render.com/docs/free)

### Supabase 無料枠の「休止」について

休止はデータ消失ではなく **一時停止** である。

- 1日数回の API アクセスがあれば、多くの場合は停止を回避できる
- GitHub Actions で週2回程度 API を ping するだけでも対策になる
- 停止してもダッシュボードから復元でき、データはディスク上に残る

個人の読書記録・家計簿アプリで週1回は触る想定なら実害は小さい。数ヶ月放置しても常時起動を求める場合は Supabase 無料枠は向かない。

### Render 無料 Web サービスの制約（API 用）

Spring API を Render にデプロイする場合の制約:

| 制約 | 内容 |
|------|------|
| スピンダウン | 15分アクセスなしで停止。次リクエストで約1分のコールドスタート |
| インスタンス時間 | 月750時間の上限あり |

個人アプリでは許容範囲だが、API レスポンスが遅く感じることがある。

### 採用パターン

#### 現状（移行期間中）

```
GitHub Pages（未デプロイ）→ Supabase Edge Functions → Supabase PostgreSQL
```

#### 短期対策: Supabase 休止の回避

移行完了までは Supabase を継続利用し、**GitHub Actions によるハートビート**（週2回程度の API ping）で休止を防ぐ。

#### 将来（推奨）

```
GitHub Pages → Render (Spring API) → Neon (PostgreSQL)
```

| 観点 | 内容 |
|------|------|
| メリット | DB に期限なし・休止なし。Spring にバックエンドを集約でき拡張性・保守性が高い |
| デメリット | Supabase Auth / Edge Functions は廃止し Spring 側で代替が必要。移行作業が発生する |

### 移行フェーズ

| フェーズ | 内容 |
|----------|------|
| 1. 現状 | Supabase（DB + Edge Functions）で開発を継続 |
| 2. 短期 | GitHub Actions でハートビートを設定し、Supabase 休止を回避 |
| 3. 中期 | `backend/` に Spring REST API を実装し Render へデプロイ |
| 4. 中期 | DB を Neon へ移行（`pg_dump` 等でデータ移行） |
| 5. 完了 | Supabase Edge Functions を廃止。フロントエンドを GitHub Pages へデプロイ |

## フロントエンド（`frontend/`）

### 技術スタック

- Angular 21 / TypeScript 5.9
- Standalone Components
- Vitest（ユニットテスト）
- SPA（将来 PWA 化予定）

### ディレクトリ構成

```
frontend/src/
├── app/
│   ├── app.ts                # ルートコンポーネント
│   ├── app.config.ts         # アプリケーション設定（DI プロバイダ等）
│   ├── app.routes.ts         # ルーティング定義
│   └── features/
│       └── reading-recorder/ # 読書記録機能
│           ├── reading-recorder.ts
│           ├── components/   # 機能内コンポーネント
│           ├── models/       # 型定義
│           └── services/     # API 呼び出し等
├── generated/openapi/        # OpenAPI から自動生成（gitignore 対象）
├── main.ts
└── styles.css
```

### ルーティング

ルートは `app.routes.ts` で管理し、各機能は `loadComponent` による遅延読み込みを採用します。

```typescript
// 例: /readingRecorder → ReadingRecorder コンポーネント
{ path: 'readingRecorder', loadComponent: () => import('./features/reading-recorder/...') }
```

### 主要コマンド

`frontend/` ディレクトリで実行:

| コマンド | 説明 |
|----------|------|
| `npm start` | 開発サーバー起動（`http://localhost:4200`） |
| `npm run build` | 本番ビルド |
| `npm test` | ユニットテスト実行 |
| `npm run openapi:generate` | OpenAPI から TypeScript 型を生成 |

### 環境変数

`angular.json` でビルド時に以下を注入する設定があります（値はビルド環境で指定）:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`

## データベース

### 方針

| 項目 | 方針 |
|------|------|
| DB ホスティング（現状） | Supabase（PostgreSQL 17） |
| DB ホスティング（将来） | Neon（PostgreSQL）。Render 無料 PostgreSQL は採用しない |
| スキーマ管理 | **`supabase/migrations/` でバージョン管理（推奨）**。Neon 移行後も同様のマイグレーション運用を継続 |
| ユーザー ID | **UUID v4**（`gen_random_uuid()` 等） |

#### スキーマ管理について（推奨: リポジトリ管理）

拡張性・保守性を優先する場合、**Supabase ダッシュボードのみでの管理ではなく、`supabase/migrations/` に SQL マイグレーションを置く方式を推奨**します。

| 観点 | ダッシュボードのみ | マイグレーション（推奨） |
|------|-------------------|-------------------------|
| 変更履歴 | 追跡困難 | Git で完全に追跡可能 |
| 環境再現 | 手動で再現が必要 | `supabase db reset` で再現可能 |
| チーム開発 | 差分の共有が難しい | PR レビューでスキーマ変更を確認可能 |
| 将来の Neon / Spring 移行 | スキーマの把握が困難 | マイグレーション履歴から移行計画を立てやすい |

**現状:** リポジトリ内にマイグレーションファイルは未整備。`config.toml` は `seed.sql` を参照していますが、ファイルも未作成です。今後マイグレーション方式へ移行する必要があります。

## 既知の問題点・改善提案

### セキュリティ

| 優先度 | 項目 | 内容 |
|--------|------|------|
| 高 | API キーのハードコード | `book.service.ts` に Supabase URL・apikey が直書きされている。環境変数へ移行すべき |
| 中 | JWT 検証無効 | `get-books` は `verify_jwt = false` + service_role で RLS をバイパス。本番運用前に再検討が必要 |

### API / 型の不整合

| 優先度 | 項目 | 内容 |
|--------|------|------|
| 高 | HTTP メソッド不一致 | OAS: `GET /books`、実装: `POST`（Supabase Function） |
| 高 | レスポンス形式不一致 | OAS: `{ items: Book[] }`、実装: 配列を直接返却 |
| 中 | ID 型不一致 | OAS: `integer`、フロント `Book.id`: `string` |
| 中 | 生成型の未使用 | `openapi:generate` があるが `BookService` は手書き型を使用 |

### フロントエンド

| 優先度 | 項目 | 内容 |
|--------|------|------|
| 高 | `provideHttpClient` 未設定 | `BookService` が `HttpClient` を使用するが `app.config.ts` に provider がない |
| 中 | `app.css` 欠落 | `app.ts` が参照する `app.css` が存在しない |
| 低 | デフォルトテンプレート残存 | `app.html` が Angular CLI のプレースホルダーのまま |

### インフラ・構成

| 優先度 | 項目 | 内容 |
|--------|------|------|
| 高 | DB マイグレーション未整備 | `supabase/migrations/`・`seed.sql` がリポジトリにない |
| 中 | Supabase 休止対策未実装 | GitHub Actions によるハートビートを設定すべき（移行完了まで） |
| 中 | PWA 未実装 | 計画段階。Service Worker・manifest の追加が必要 |
| 低 | ルート README なし | 新規参加者向けのエントリポイントがない |
| 低 | `deploy-function.js` の import map 指定 | `deno.json` を指定しているが、本体は `import-map.json`（動作要確認） |
